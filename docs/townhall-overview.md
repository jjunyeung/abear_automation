# 윈들리 자동화 테스트 시스템 — 개요

---

## 1. 한 줄 요약

윈들리 웹앱의 실제 사용자 시나리오를 **자동으로 실행**하고, 결과를 **Slack으로 요약 리포트**로 받는 시스템이다.

- 실제 브라우저(Chrome + 윈들리 확장)로 사람이 클릭하듯 동작
- 현재 **1,573개 테스트 케이스 / 10개 도메인** 커버
- 매일 새벽 자동 실행 → 정오에 일일 다이제스트 발송

---

## 2. 어떻게 구현했나

### 핵심 아이디어 — "테스트를 코드가 아니라 시나리오로 쓴다"

테스트 케이스를 QA가 매번 코드로 짜는 대신, **자유 양식에 가까운 YAML(시나리오 대본)** 로 선언하고, 그걸 실행 엔진이 실제 브라우저 동작으로 변환한다.

```yaml
title: 단건 상품 업로드 후 등록상품 목록 검증
inputs:
  source_product_id: { type: string, example: '235442266' }
steps:
  - id: open_search_modal
    do: 상품 코드 검색 모달 열기
  - id: search
    do: source_product_id 로 검색
  - id: upload
    do: 업로드 실행
    on_error: [upload_confirm_btn_not_found]   # 에러 나면 이 복구를 탐
expected: 업로드 성공 + 등록상품 목록에 매칭. unhandled 0건.
```

- `**atcs/*.atc.yml**` — 시나리오 대본 (선언형, 사람이 읽고 씀)
- `**tests/*.spec.ts**` — 각 step을 실제 Playwright 동작으로 매핑
- `**lib/**` — 실행 엔진(runner), 로그인/공통 액션, 에러 정의
- `**recoveries/<에러>.ts**` — 에러별 자동 복구 코드

### 기술 스택

- **Playwright** (브라우저 자동화) + **윈들리 Chrome 확장** 로딩
- 실제 로그인 세션을 유지한 채 `app.windly.cc`를 사람처럼 조작
- 모든 실행은 고정 창 크기(1800×1280)로 일관되게

## 3. 어떻게 동작하나 (실행 → 복구 → 리포트)

```
  [스케줄러(macOS launchd)]  매일 새벽 자동 발화
            │
            ▼
  [ATC 실행]  시나리오를 순서대로 실제 브라우저로 실행
            │
            ├─ 정상 → ✅ 성공 기록
            │
            ├─ 에러 발생 → [자동 복구]  recoveries/ 에 해당 복구가 있으면
            │                          자동으로 고친 뒤 실패 지점부터 재개
            │
            └─ 복구 불가/외부 요인 → ⏭️ 미실행 or ❌ 실패로 명확히 기록
            │
            ▼
  [리포트 생성]  실행 건별 md/json + 하루치 묶음 리포트
            │
            ▼
  [Slack 발송]  정오에 일일 다이제스트 1회 요약 전송
```

### 자동 복구가 핵심 차별점

일반 자동화 테스트는 에러가 나면 그냥 실패한다. 이 시스템은 **알려진 에러 유형이면 스스로 고친다.**

- 예: "이미지 누락", "상품명 너무 김", "에러체크 탭 빨간불", "업로드 확인 버튼 못 찾음" 등
- 현재 **12종의 자동 복구** 등록됨
- 고칠 수 없는 외부 요인(예: 플랜 사용량 초과, 수집 실패)은 억지로 고치지 않고 **명확한 원인으로 리포트** → 사람이 판단

### 매일 받는 리포트


| 종류                | 내용                               | 위치                 |
| ----------------- | -------------------------------- | ------------------ |
| **묶음(batch) 리포트** | 하루 실행분 전체 목차 + 본문                | `reports/batches/` |
| **일일 다이제스트**      | 총 실행/PASS/FAIL/미실행 통계 + Slack 발송 | `reports/digests/` |


실제 예시 (2026-07-06 다이제스트):

```
# 일일 다이제스트 — 2026-07-06
- 총 batch: 1
- 총 ATC: 14
- ✅ PASS: 12   ❌ FAIL: 1   ⏭️ 미실행: 1
```

각 케이스는 `✅ 성공 / ❌ 실패 / ⏭️ 미실행`으로 명확히 구분되고, 실패 시 어느 단계에서 무슨 에러가 났는지까지 기록된다.

## 4. 주요 기능 정리

- **선언형 시나리오** — 개발 지식 없이도 YAML 대본으로 테스트 케이스 추가/수정
- **실제 브라우저 실행** — 윈들리 확장까지 로드해 진짜 사용자 환경과 동일
- **자동 복구** — 알려진 에러는 스스로 고치고 실패 지점부터 재개
- **스마트한 실패 처리** — 고칠 수 있는 것/외부 요인/일회성 문제를 구분해서 노이즈 최소화
- **스케줄 실행** — 매일 밤 무인 자동 실행 (사람 개입 불필요)
- **자동 재시도** — 스케줄 실행 중 실패한 케이스는 1회 자동 재시도
- **Slack 리포트** — 매일 정오 요약 자동 발송, 실패만 빠르게 파악 가능
- **GUI 러너** — 원할 때 데스크톱 앱에서 개별 케이스를 골라 수동 실행/결과 확인
- **넓은 커버리지** — 수집상품/등록상품/배대지/주문관리/기본설정/업로드/e2e 등 10개 도메인, 1,573개 케이스
